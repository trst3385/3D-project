📚 [개념 정리] C# 구조체 (Struct) 완벽 이해하기
1. 구조체(Struct)란?
"변수 종합 선물 세트"
서로 관련 있는 여러 개의 변수(hp, damage, speed 등)를 하나의 바구니에 담아 사용자 정의 데이터 타입(규격)으로 묶어주는 공간.

2. 독립된 파일로 분리하는 이유 (전역 구조체)
특정 클래스(예: Monster.cs) 내부에 구조체를 선언하면 다른 클래스(예: Player.cs, Item.cs)에서 접근하기 까다로워짐.
아무 클래스도 속하지 않은 독립된 C# 파일(예: Stats.cs)로 빼두면, 유니티 프로젝트 전역에서 누구나 가져다 쓸 수 있는 공용 규격이 됨.
인스펙터 창에 노출하려면 반드시 [System.Serializable] 속성을 붙여주어야 함.

3. 구조체의 핵심 특징 (클래스와의 차이점)
값 형식 (Value Type):
클래스(class)는 참조 형식이라 주소값이 복사되지만, 구조체는 대입하거나 전달할 때 데이터 그 자체가 통째로 복사(값 복사)됨.
원본 데이터가 바뀌어도 복사본에 영향을 주지 않으며, 주로 가벼운 데이터 묶음(좌표, 스탯 등)을 다룰 때 적합함.
함수와 생성자 포함 가능:
단순히 변수만 모아두는 것을 넘어, 내부 데이터를 활용하는 간단한 로직(함수)이나 생성자도 함께 작성할 수 있음.

4. 실무적 활용 (데이터 구조 설계)
틀(구조체): 데이터의 생김새(변수 구성)를 정의함 (예: StatStruct).
값(ScriptableObject / 인스펙터): 기획 데이터 원본인 SO(ScriptableObject)나 인스펙터 창에서 그 틀에 실제 수치를 채워 넣음.
적용: 몬스터나 플레이어 스크립트는 그 공용 틀을 변수로 선언(public StatStruct stats;)하여 받아오고, 하드코딩을 방지하며 유연한 데이터 관리가 가능해짐.


1. 스트럭은 그냥 "변수 종합 선물 세트"
어렵게 생각할 것 없이, 그냥 float hp;, float mp;, float atk;를 한 바구니에 담아두고 "앞으로 이건 Stat이라는 이름의 세트로 부르자!" 하고 묶어놓은 공간일 뿐입니다. 그 이상 그 이하도 아닙니다.
2. 드래그&드롭의 귀찮음 vs 밤새 에러 고치는 지옥
오브젝트마다 SO 연결하고 스트럭 선언하고... 처음 세팅할 때는 분명히 파일도 여러 개 만들어야 하고 연결해야 하니 귀찮은 게 맞습니다. 질문자님의 지적이 정확해요.
하지만 진짜 개발자들이 이 귀찮음을 기꺼이 감수하는 이유는, 초반의 귀찮음 10%가 나중에 프로젝트가 커졌을 때 터질 90%의 대형 버그와 밤샘 디버깅을 막아주기 때문입니다.
• 만약 이 구조 없이 대충 짜면, 나중에 몬스터 50마리의 데미지를 10씩 올리고 싶을 때 프리팹 50개를 일일이 열어서 수정해야 하거나 스크립트 수천 줄을 눈으로 쫓아가며 하드코딩을 고쳐야 합니다.
• 하지만 이 '귀찮은 구조'를 짜두면? SO 파일 몇 개만 딸깍 수정하면 게임 전체가 완벽하게 바뀝니다.

💡 진짜 공부는 이렇게 하는 것입니다
1. 스트럭을 독립된 파일로 빼는 이유 (전역 구조체)
만약 스트럭을 Monster.cs 스크립트 안에 적어두면, 나중에 플레이어(Player.cs)나 아이템(Item.cs) 스크립트에서 그 스탯 구조를 쓰고 싶을 때 Monster.StatStruct라고 복잡하게 이름을 불러와야 하거나 쓸 수 없게 됩니다.
그래서 아래처럼 아무 클래스에도 속하지 않는 독립된 파일로 만듭니다.
클래스(class)는 '참조 형식'이라서 변수를 복사하면 원본 주소값이 복사되지만, 스트럭(struct)은 '값 형식'이라서 대입하거나 다른 곳에 넘길 때 데이터 그 자체가 통째로 복사돼.

그래서 원본이 바뀌어도 복사본에 영향을 주지 않고, 메모리(스택)에 가볍게 생성되었다가 사라지는 데이터(예: 위치 좌표, 스탯 등)를 다룰 때 아주 유리해.

요약하자면 평소에는 데이터를 묶어두는 '변수 종합 선물 세트'로 쓰지만,

💡 실제 파일 구성 방법
유니티에서 Stats.cs라는 이름으로 새 C# 스크립트를 만들고, 안에 있는 MonoBehaviour나 class 내용을 싹 다 지운 뒤 스트럭만 덜렁 적어놓습니다.

// 파일명: Stats.cs
using UnityEngine;

[System.Serializable] // ⭐ 이 한 줄을 적어줘야 유니티 인스펙터 창에 눈으로 보입니다!
public struct StatStruct
{
    public float hp;
    public float damage;
    public float speed;
}

이렇게 해두면 이 스트럭은 프로젝트 전체에서 쓸 수 있는 '공용 규격(데이터 타입)'이 됩니다. 마치 우리가 int, float, string을 아무 데서나 가져다 쓰는 것처럼 말이죠.
2. 그럼 오브젝트 스크립트에는 무엇을 적나요?
오브젝트(몬스터나 플레이어) 스크립트에는 방금 만든 공용 규격을 가져와서 "내 가방에 넣겠다"라고 변수 선언만 해주는 것입니다.

// 파일명: Monster.cs
using UnityEngine;

public class Monster : MonoBehaviour
{
    // 위에서 만든 공용 스트럭 규격을 내 멤버 변수로 선언!
    public StatStruct currentStats;
